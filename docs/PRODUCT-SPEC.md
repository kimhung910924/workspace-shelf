# Workspace Shelf 제품 기획서

> 문서 상태: 구현 기준 v1  
> 작성일: 2026-07-30  
> 대상: 김흥기 개인용 macOS 앱  
> 원문 보존: `WORKSPACE-SHELF-기획서.md`

## 1. 한 문장 정의

Workspace Shelf는 화면 상단 중앙의 노치 영역에 마우스를 대거나
`Option + Space`를 눌렀을 때 아래로 펼쳐져, 자주 쓰는 폴더와 파일을
Finder보다 짧은 동선으로 탐색·실행·드래그할 수 있게 하는 macOS 전용
개인 파일 허브다.

## 2. 해결할 문제

현재 반복 작업은 파일 자체를 편집하는 일이 아니라, 파일이 있는 장소로
이동하는 일에서 불필요한 시간이 생긴다.

- 여러 Finder 창 중 원하는 창을 다시 찾는다.
- 개발, 소설, Suno, 영상, Drive 폴더의 깊은 경로를 반복해서 이동한다.
- 파일을 ChatGPT, Canva, CapCut, Terminal 같은 다른 앱으로 넘기기 위해
  Finder를 먼저 연다.
- 다운로드 폴더에서 최근 파일을 찾고 목적지 앱으로 옮기는 동선이 길다.
- 메뉴바 런처는 앱 실행에는 좋지만 폴더 내부 탐색에는 부족하다.

이 앱은 Finder를 대체하지 않는다. 자주 쓰는 루트 폴더로 들어가는 첫
2~5단계를 없애고, 파일을 다음 앱으로 넘기는 순간까지를 짧게 만든다.

## 3. 제품 목표

### 3.1 최우선 목표

1. 어느 앱을 사용 중이든 1초 안에 패널을 연다.
2. 등록한 작업 폴더를 두 번 이하의 선택으로 연다.
3. 파일을 기본 앱에서 열거나 외부 앱으로 바로 드래그한다.
4. 앱 재실행 뒤에도 폴더 권한과 마지막 탐색 위치가 가능한 범위에서
   복원된다.
5. 첫 버전은 사용자 파일을 변경하지 않는 읽기 중심 동작으로 안전하게
   실사용할 수 있다.

### 3.2 성공 지표

서버 분석은 넣지 않으며 수동으로 판단한다.

| 항목 | 목표 |
|---|---|
| 패널 체감 호출 시간 | 1초 미만 |
| 기본 작업 폴더 진입 | 패널 호출 후 2회 이하 선택 |
| 앱 재실행 후 등록 폴더 복원 | 등록 폴더의 95% 이상 |
| 일주일 실사용 중 파일 손상 | 0건 |
| 주요 패널 호출 실패 | 하루 1회 미만 |
| Finder를 별도로 열지 않고 완료한 파일 접근 | 자주 쓰는 흐름의 절반 이상 |

## 4. 비목표

초기 제품은 다음이 아니다.

- Finder 전체 대체 앱
- 파일 동기화 또는 백업 앱
- Google Drive, Dropbox, iCloud 자체 클라이언트
- 파일 내용 인덱싱 검색 엔진
- 협업, 계정, 서버, 결제, 구독 제품
- Windows/iOS/iPadOS 앱
- App Store 배포 제품
- 원격 파일 프로토콜 클라이언트
- Git GUI 또는 IDE
- 환자 정보 관리 시스템

## 5. 사용 환경

- Apple Silicon Mac
- macOS 14 이상
- 노치가 있는 MacBook과 일반 외부 모니터
- 다중 디스플레이 가능
- Google Drive for desktop의 로컬 마운트 폴더 사용 가능
- 개인이 Xcode 또는 로컬 빌드 스크립트로 설치

앱은 개인 경로를 코드에 넣지 않는다. 모든 작업 루트는 사용자가
`NSOpenPanel`에서 선택한다.

## 6. 핵심 용어

### Shelf

상단 중앙에서 아래로 펼쳐지는 하나의 플로팅 패널.

### Workspace

사용자가 등록한 루트 폴더. 예: Omni, Novel, Suno, Downloads.

### Browser

선택된 Workspace 안을 이동하는 파일 목록 영역.

### Trigger zone

현재 화면의 상단 중앙에 있는 보이지 않는 마우스 감지 영역. 노치가
있으면 노치 주변, 없으면 메뉴바 중앙 역할을 한다.

### Pinned

다른 곳을 클릭해도 패널을 닫지 않는 상태.

## 7. 주요 사용자 여정

### 7.1 노치로 열고 파일 실행

1. 포인터를 현재 화면 상단 중앙으로 이동한다.
2. 포인터가 trigger zone에 약 0.2초 머문다.
3. Shelf가 상단 중앙에서 열린다.
4. 마지막 Workspace와 마지막 경로가 보인다.
5. 파일을 더블클릭한다.
6. macOS 기본 앱이 파일을 연다.
7. 고정되지 않은 Shelf는 앱 전환 또는 외부 클릭 후 닫힌다.

완료 기준:

- Dock 아이콘이나 Finder를 누를 필요가 없다.
- 패널이 포인터가 있던 디스플레이에 나타난다.
- 패널은 화면 밖으로 잘리지 않는다.

### 7.2 단축키로 열고 프로젝트 폴더 이동

1. `Option + Space`를 누른다.
2. Shelf가 열린다.
3. 왼쪽에서 `Omni`를 선택한다.
4. 하위 폴더를 더블클릭한다.
5. 우클릭 메뉴에서 `Terminal에서 열기`를 선택한다.

완료 기준:

- 시스템 어디서나 같은 단축키가 동작한다.
- 동일 단축키를 다시 누르면 Shelf가 닫힌다.

### 7.3 파일을 다른 앱으로 끌기

1. Shelf에서 이미지, 오디오, 문서 파일을 찾는다.
2. 파일 행을 누른 채 Finder 또는 다른 앱의 드롭 영역으로 끈다.
3. 대상 앱이 원본 파일 URL을 받는다.

완료 기준:

- 대상 앱이 원본 이름 그대로의 파일을 받는다.
- Finder로 끌면 Finder와 같은 규칙을 따른다. 같은 볼륨이면 이동,
  다른 볼륨이면 복사다.
- 업로드 영역처럼 복사만 받는 대상에서는 원본이 그대로 남는다.
- Finder, ChatGPT 업로드 영역, 일반 macOS 파일 드롭 영역에서 표준
  파일 드래그로 인식된다.

### 7.4 새 Workspace 등록

1. 메뉴바 또는 Shelf의 `폴더 추가`를 누른다.
2. macOS 폴더 선택 창에서 폴더 하나를 고른다.
3. 기본 표시 이름은 폴더명으로 생성된다.
4. Workspace가 목록 마지막에 추가되고 선택된다.
5. 앱을 다시 실행해도 Workspace가 복원된다.

오류 상태:

- bookmark 생성 실패: 등록하지 않고 오류 메시지를 보인다.
- 폴더가 이동됨: stale bookmark를 갱신한다.
- 권한 상실: 연결 끊김 상태와 `다시 연결` 행동을 제공한다.
- 클라우드 볼륨 미마운트: 앱은 종료되지 않고 사용할 수 없음으로 표시한다.

## 8. 화면 구조

기본 크기는 780 × 500pt, 최소 크기는 560 × 340pt다.

```text
┌─────────────────────────────────────────────────────────────────┐
│  Workspace Shelf     ←  ↑   현재 경로          ⟳   목록  📌   │
├────────────────┬────────────────────────────────────────────────┤
│ Omni           │ 이름                     수정일       크기      │
│ Novel          │ docs/                    오늘                   │
│ Suno           │ README.md                오늘         12 KB     │
│ Downloads      │ sample.wav               어제         48 MB     │
│                │                                                │
│ + 폴더 추가     │                                                │
└────────────────┴────────────────────────────────────────────────┘
```

### 8.1 패널 외형

- 시스템 다크/라이트 모드에 맞는 재질 배경
- 모서리 반경 18pt
- 얇은 시스템 separator 테두리
- 과한 브랜드 색, 그라데이션, 배경 이미지 없음
- 기본 macOS 서체와 SF Symbols 사용
- 창 제목바와 traffic-light 버튼은 보이지 않음
- 시스템 그림자를 사용해 다른 앱 위의 임시 도구임을 표시

### 8.2 상단 툴바

왼쪽부터:

1. 앱 이름 또는 현재 Workspace 이름
2. 뒤로
3. 상위 폴더
4. 현재 상대 경로
5. 새로고침
6. 보기 방식
7. 고정

상태:

- 이동 불가능한 뒤로/상위 버튼은 disabled
- loading 중 새로고침 아이콘은 progress로 대체 가능
- 고정 상태는 채워진 pin 아이콘과 접근성 라벨로 표현

### 8.3 Workspace 사이드바

- 폭 176pt
- 등록 순서대로 세로 목록
- 각 행은 SF Symbol, 이름, 접근 오류 표시로 구성
- 선택 행은 macOS accent color의 약한 배경
- 하단에 `폴더 추가`
- 우클릭: Finder에서 보기, 이름 변경, 목록에서 제거
- 제거는 등록 정보만 삭제하며 원본 폴더는 절대 삭제하지 않음

### 8.4 Browser

첫 버전은 리스트 보기를 기본으로 한다.

열:

- 이름
- 수정일
- 크기

행 동작:

- 한 번 클릭: 선택
- 두 번 클릭한 폴더: 진입
- 두 번 클릭한 파일: 기본 앱에서 열기
- 드래그: 표준 파일 URL 제공
- 우클릭: 열기, Finder에서 보기, Terminal에서 열기(폴더), 경로 복사,
  파일명 복사

폴더는 같은 정렬 그룹에서 항상 파일보다 위에 둔다.

### 8.5 빈 상태

등록 Workspace가 없을 때:

- 제목: `자주 쓰는 폴더를 추가하세요`
- 설명: `폴더는 이동하거나 복사하지 않고, 빠른 접근 경로만 저장합니다.`
- 주 행동: `폴더 추가`

폴더가 비었을 때:

- 제목: `이 폴더는 비어 있습니다`
- 상위 이동과 외부 파일 드롭은 단계에 따라 제공

접근 오류일 때:

- 제목: `폴더에 접근할 수 없습니다`
- 원인 요약
- `다시 연결`, `Finder에서 확인`, `목록에서 제거`

## 9. 패널 동작 규칙

### 9.1 열기

열기 경로:

- `Option + Space`
- 메뉴바 아이콘 클릭
- trigger zone hover

열릴 때:

1. 포인터가 있는 디스플레이를 선택한다.
2. 해당 디스플레이의 `visibleFrame` 상단 중앙을 기준으로 위치를 계산한다.
3. 패널 폭이 화면보다 크면 안전 여백 안으로 줄인다.
4. 패널을 key window로 만들고 현재 경로를 새로고침한다.
5. 애니메이션은 120~180ms 범위에서 opacity와 짧은 y 이동만 사용한다.

### 9.2 닫기

다음 상황에서 닫는다.

- `Escape`
- 같은 전역 단축키 재입력
- 고정되지 않은 상태에서 패널 밖 클릭
- 메뉴바의 닫기 동작

다음 상황에서는 닫지 않는다.

- 고정 상태의 외부 클릭
- 파일 우클릭 메뉴 사용 중
- `NSOpenPanel`로 Workspace를 추가하는 중
- Quick Look이 활성화된 이후의 2차 구현

### 9.3 trigger zone

초기 규칙:

- 현재 화면 frame 상단 4pt
- 수평 중심 기준 좌우 100pt
- 진입 후 180ms dwell
- 열린 직후 800ms 동안 재호출 방지
- 사용자가 빠르게 상단을 스쳐 지나가면 열지 않음

노치 실측 API에 의존하지 않는다. 노치가 없는 외부 모니터에서도 같은
상단 중앙 제스처가 작동한다.

### 9.4 다중 디스플레이

- 단축키는 포인터가 있는 디스플레이를 기준으로 한다.
- hover는 이벤트가 발생한 포인터 디스플레이를 기준으로 한다.
- 메뉴바 아이콘으로 열 때도 포인터 디스플레이를 우선한다.
- 디스플레이 연결이 바뀌면 저장 좌표를 신뢰하지 않고 다시 계산한다.

## 10. Workspace 데이터 계약

저장 레코드:

```json
{
  "version": 1,
  "workspaces": [
    {
      "id": "UUID",
      "name": "Omni",
      "bookmarkData": "base64",
      "iconName": "hammer",
      "colorName": "blue",
      "sortOrder": 0,
      "lastRelativePath": "docs"
    }
  ]
}
```

저장 위치:

```text
~/Library/Application Support/WorkspaceShelf/workspaces.json
```

규칙:

- 절대 경로는 주 저장 식별자가 아니다.
- bookmark가 stale이면 갱신한 데이터를 다시 저장한다.
- 앱이 접근을 시작한 URL은 교체·제거·종료 시 접근을 끝낸다.
- 복원 실패한 레코드는 자동 삭제하지 않는다.
- JSON을 쓸 때 임시 파일을 이용한 atomic write를 사용한다.
- 알 수 없는 필드는 향후 버전 마이그레이션에서 무시할 수 있다.

## 11. 탐색 규칙

### 11.1 루트 경계

- Browser의 최상위는 선택한 Workspace URL이다.
- `상위 폴더`로 Workspace 밖에 나갈 수 없다.
- 심볼릭 링크는 목록에는 표시하되, 대상이 루트 밖이면 진입 전 확인 또는
  차단 정책을 적용한다.
- macOS 패키지는 기본적으로 파일처럼 취급한다.

### 11.2 목록 로딩

- UI main thread에서 디렉터리를 열거하지 않는다.
- 파일 내용은 읽지 않는다.
- 필요한 resource key만 조회한다.
- 숨김 파일은 기본적으로 제외한다.
- 패키지 내부를 자동 재귀 탐색하지 않는다.
- 로딩 도중 다른 폴더로 이동하면 오래된 결과를 화면에 적용하지 않는다.

조회 정보:

- `isDirectory`
- `isPackage`
- `isHidden`
- `contentModificationDate`
- `fileSize`
- `localizedName`
- `contentType` 또는 확장자

### 11.3 정렬

기본:

1. 폴더 우선
2. 사용자가 선택한 정렬 기준
3. 이름 localized standard compare를 tie-breaker로 사용

정렬 기준:

- 이름 오름/내림
- 수정일 최신/오래된 순
- 종류 오름/내림
- 크기 오름/내림(파일만 의미 있음)

Workspace별 마지막 정렬은 2차, 앱 전체 정렬 저장은 1차 구현 범위다.

### 11.4 마지막 경로

- Workspace를 떠날 때 현재 경로를 루트 기준 상대 경로로 저장한다.
- 다시 선택할 때 경로가 여전히 루트 내부이고 존재하면 복원한다.
- 존재하지 않거나 접근할 수 없으면 루트로 돌아간다.

## 12. 파일 행동

### 12.1 첫 구현에 허용

- 기본 앱에서 열기
- Finder에서 보기
- 폴더를 Terminal에서 열기
- 전체 경로 복사
- 파일명 복사
- 외부 앱으로 드래그

### 12.2 MVP 후반에 추가

- 외부 파일을 현재 폴더로 복사
- 새 폴더
- 이름 변경
- 복사/붙여넣기
- 여러 항목 선택
- 휴지통으로 이동

### 12.3 금지

- 영구 삭제
- 묻지 않는 덮어쓰기
- 등록 폴더 전체의 일괄 변경
- symbolic link를 따라가는 재귀 삭제
- 패키지 내부의 암묵적 변경

## 13. 드래그앤드롭 계약

### 13.1 Shelf에서 외부로

- 드래그 payload는 표준 file URL이다. 파일 내용을 새 문서로 써 보내지
  않는다.
- 파일과 폴더 모두 가능하다.
- 제공하는 operation은 `[.move, .copy]`이며, 무엇을 수행할지는 받는
  쪽이 고른다. 드래그 시작만으로는 아무것도 바꾸지 않는다.
- 이동이 일어나면 현재 폴더 감시자가 목록을 갱신한다.
- 여러 항목은 다중 선택 구현 이후 제공한다.

검증 대상:

- Finder
- ChatGPT 파일 업로드 영역
- Canva 또는 브라우저 업로드 영역
- CapCut 또는 영상 편집 앱

### 13.2 외부에서 Shelf로

첫 코드 슬라이스에서는 제외한다.

추가 시 원칙:

1. drop operation 기본값은 copy
2. 현재 폴더와 동일한 source는 무시
3. 충돌이 없으면 임시 이름 또는 atomic 가능한 복사 사용
4. 충돌 시 `건너뛰기`, `이름 바꾸어 복사`, `대치`를 명시
5. 대치는 별도 확인 없이는 실행하지 않음
6. 진행률과 실패 항목을 표시
7. 원본은 절대 삭제하지 않음

## 14. 단축키와 접근성

| 키 | 동작 | 단계 |
|---|---|---|
| `Option + Space` | Shelf 토글 | 1 |
| `Escape` | Shelf 닫기 | 1 |

오류, 고정 상태를 구분하지 않는다.

## 15. 오류 처리

사용자 메시지는 `무슨 문제가 생겼는지 + 지금 할 수 있는 행동`으로 쓴다.

| 상황 | 표시 | 복구 |
|---|---|---|
| 폴더 미존재 | 폴더를 찾을 수 없음 | 다시 연결 / 제거 |
| 접근 권한 없음 | 접근 권한 필요 | 다시 연결 |
| Drive 오프라인 | 현재 사용할 수 없음 | Finder 확인 / 재시도 |
| 목록 로딩 실패 | 폴더 내용을 불러오지 못함 | 새로고침 |
| 파일 열기 실패 | 기본 앱에서 열지 못함 | Finder에서 보기 |
| Terminal 실행 실패 | Terminal을 열지 못함 | 경로 복사 |
| bookmark 저장 실패 | 폴더를 등록하지 못함 | 다시 선택 |

오류 때문에 전체 앱을 종료하지 않는다. 상세 오류는 개발 로그에만 남기며,
사용자 파일의 전체 경로를 장기 로그에 축적하지 않는다.

## 16. 성능 기준

- warm 상태 패널 표시: 150ms 목표
- 폴더 1,000개 항목 목록: 1초 내 첫 결과 목표
- 패널을 닫아도 등록 Workspace와 현재 목록 상태는 메모리에 유지
- 썸네일은 화면에 보이는 항목만 요청
- 대용량 파일의 내용을 목록 단계에서 읽지 않음
- hover monitor에서 파일 I/O나 화면 갱신 수행 금지
- 연속 디렉터리 이동 시 이전 비동기 결과 무시

## 17. 개인정보와 권한

- 네트워크 요청 없음
- 분석/원격 로그 없음
- 등록 폴더명과 bookmark는 로컬에만 저장
- 전체 디스크 접근을 기본 요구하지 않음
- 키 입력 전체를 감시하지 않고 등록된 Carbon hot key만 수신
- mouse trigger는 좌표만 사용하고 클릭 내용이나 앱 정보를 기록하지 않음
- Clinic 같은 민감 폴더를 예제 데이터나 테스트 fixture로 사용하지 않음

## 19. MVP 인수 조건

다음을 모두 만족해야 MVP 완료로 본다.

1. 앱을 `.app`으로 실행하고 메뉴바에서 찾을 수 있다.
2. `Option + Space`로 반복해서 열고 닫을 수 있다.
3. 상단 중앙 hover로 의도적으로 열 수 있고 스쳐 갈 때 과도하게 열리지 않는다.
4. 포인터가 있는 화면의 상단 중앙에 패널이 나타난다.
5. 3개 이상의 폴더를 등록하고 재실행 뒤 복원한다.
6. Workspace 밖으로 상위 이동할 수 없다.
7. 파일과 폴더를 구분해 목록으로 표시한다.
8. 파일 더블클릭, Finder reveal, Terminal 열기, 경로 복사가 동작한다.
9. 파일을 Finder와 최소 한 개 외부 앱으로 드래그할 수 있다.
10. 외부 파일 drop 시 원본을 보존하고 충돌 전 확인한다.
11. 접근할 수 없는 Drive 폴더가 있어도 다른 Workspace는 사용할 수 있다.
12. 등록 삭제가 원본 폴더를 삭제하지 않는다.
13. `swift test`, Debug build, Release build가 성공한다.
14. 실제 테스트 폴더로 1주간 사용하며 파일 유실이 없다.

- 로그인 시 자동 실행

것이다. 실사용 결과를 확인한 뒤 쓰기 기능을 추가한다.
